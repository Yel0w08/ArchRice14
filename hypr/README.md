# Hyprland Rice (Caelestia-based)

A [Caelestia](https://github.com/caelestia-dots)-style Hyprland setup where the
config is **Lua-generated** rather than a plain `hyprland.conf`.

## Layout

```
hypr/
├── hyprland.lua            # entry point; sources the modules below
├── hyprland-gui.lua        # GUI/launcher helpers
├── variables.lua           # shared vars (keybinds, themes, app ids)
├── hyprland/               # generated per-section config
│   ├── keybinds.lua        # system keymap (225 lines)
│   ├── execs.lua           # autostart / window rules
│   ├── animations.lua
│   ├── decoration.lua
│   ├── env.lua             # toolkit env vars (Qt/GTK/Wayland)
│   ├── general.lua
│   ├── gestures.lua
│   ├── group.lua
│   ├── input.lua
│   ├── misc.lua
│   └── rules.lua
├── scheme/                 # colour scheme (current/default)
├── utils/                  # lua helpers (functions, json)
└── caelestia-user/         # USER-OVERRIDES (loaded last, additive)
    ├── hypr-user.lua       # custom keybinds, ported from KDE Plasma
    └── hypr-vars.lua       # user var overrides (e.g. terminal)
```

## Keybinds

Keybinds live in **two** files:

- `hyprland/keybinds.lua` — the full system keymap shipped by Caelestia.
- `caelestia-user/hypr-user.lua` — **additive custom binds** ported from KDE
  Plasma's `keymap.kksrc`. Loaded *after* the system keymap, so nothing existing
  is rebound or removed.

### Notable custom binds (from `hypr-user.lua`)

| Keys | Action |
|------|--------|
| `Super + Space` / `Alt + F2` | Launcher (KRunner-style) |
| `Super + Return` / `Ctrl + Alt + T` | Terminal |
| `Super + F9` / `Super + F10` | Expose / Expose-all |
| `Super + Shift + A` | Previous workspace |
| `Super + Escape` | System monitor |
| `Super + Ctrl + Escape` | Force-kill window |

## Notes

- The config is generated by the Lua at runtime; edit the `.lua` sources, not a
  compiled output.
- `caelestia-user/` is the safe place for personal overrides — it is designed to
  be additive and survive upstream keymap updates.
- No usernames, hostnames, or machine-specific paths are included; app paths use
  generic locations (`/usr/bin/...`).
